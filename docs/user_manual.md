# 历史时间对照 Agent 使用手册

本文面向日常使用者和内部运营者，说明如何启动系统、登录聊天、管理会话、使用 Agent 查询历史事件，以及如何维护事件库、知识库和数据质量。

## 1. 系统入口

### 本地访问地址

| 服务 | 默认地址 | 说明 |
|---|---|---|
| 前端工作台 | `http://127.0.0.1:5174` | 聊天、会话、管理后台入口 |
| 后端 API | `http://127.0.0.1:19000` | FastAPI 服务 |
| API 文档 | `http://127.0.0.1:19000/docs` | Swagger 调试入口 |

### 启动顺序

1. 启动后端。
2. 启动前端。
3. 打开前端工作台并登录。

前端默认会请求 `http://127.0.0.1:19000`。如需修改 API 地址，可在前端环境变量中设置：

```bash
VITE_API_BASE_URL=http://127.0.0.1:19000
```

## 2. 账号和登录

### 注册

在登录页切换到注册模式，输入用户名和密码即可创建账号。注册后可直接登录。

### 登录

登录成功后，系统会通过 HttpOnly session 识别当前用户。登录后可使用：

- 聊天记录保存
- 会话列表
- 聊天组
- AI Memory 召回
- 个人记忆管理

### 登出

点击侧边栏用户区域的登出按钮。登出后会清空当前前端会话视图，聊天记录仍保存在后端。

## 3. 聊天功能

### 提问方式

在聊天输入框输入历史问题，例如：

- `755年中国发生安史之乱时，中东和中亚发生了什么？`
- `对比600到650年东亚和中东的重大变化`
- `怛罗斯之战和唐朝、中亚、阿拉伯帝国有什么关系？`
- `帮我生成一张700到800年欧亚大陆历史对照表`

Agent 会根据问题自动选择工具，常见能力包括：

- 按年份查询历史事件
- 按时间段查询历史事件
- 按地区生成横向对照
- 查看事件详情
- 查找关联事件
- 检索知识库资料
- 生成事件修订草案或来源核验草案

### 流式输出

回答会逐段生成。界面会显示当前阶段，例如：

- 正在建立研究任务
- 正在查询历史资料
- 工具已返回，正在整理证据
- 正在生成回答
- 回答完成

### 停止生成

回答生成过程中可以点击停止按钮。前端会立即停止显示流式内容，并尽力通知后端取消当前 Agent run。

### 回答结构

一次回答通常包含：

- 主回答：自然语言解释或表格
- 事件卡片：查询到的历史事件
- 引用来源：事件来源或知识库 chunk
- 执行过程：Agent 调用过的工具和状态
- Langfuse trace 链接：如果后端配置了 Langfuse

## 4. 会话和聊天组

### 新建会话

点击新建会话后，当前聊天区会回到欢迎状态。发送第一条消息后，系统会自动保存会话。

### 会话自动标题

新会话在首轮回答后会尝试根据问题自动生成标题。用户也可以手动重命名。

### 重命名会话

在侧边栏会话列表中进入重命名状态，输入新的标题并确认。

### 归档会话

不再常用的会话可以归档。归档后默认不显示，可切换到归档视图查看。

### 聊天组

聊天组用于按主题整理会话，例如：

- 唐朝专题
- 中亚与阿拉伯帝国
- 8 世纪世界史

用户只能看到自己的聊天组和会话。

## 5. AI Memory

AI Memory 基于用户自己的聊天记录生成，不会跨用户共享。

当前支持：

- 会话摘要
- 长期记忆候选
- 长期记忆创建
- 记忆召回
- 禁用或删除记忆

记忆只用于理解用户偏好和研究兴趣，不能覆盖系统规则，也不能授权工具调用。后端会把长期记忆作为“不可信上下文”注入 Agent。

## 6. 人工确认

某些高风险操作不会直接执行，例如：

- 修改事件主记录
- 修改来源信息
- 应用 Agent 生成的事件修订草案
- 应用来源核验草案

当 Agent 需要执行高风险工具时，聊天界面会显示确认面板。

确认面板会展示：

- 操作类型
- 目标事件或来源
- 字段变化 diff
- 风险说明
- 原始工具参数

只有管理员账号可以点击“确认并继续执行”。普通用户不能确认高风险操作。

安全规则：

- 模型不能自行设置 `confirmed=true`
- 前端不能篡改待确认参数
- 后端确认恢复时只使用数据库中保存的 pending 参数
- 重复确认不会重复执行

## 7. 管理后台

管理员登录后可进入 `/admin` 管理后台。

### 管理总览

展示系统数据资产概况：

- 事件数量
- 待审核批次
- 低置信事件
- 无来源事件
- 知识文档数量
- 向量覆盖率

### 数据导入

支持粘贴或上传 JSON/CSV 风格的历史事件数据。导入不会直接写入正式事件库，而是先进入 staging。

导入流程：

1. 创建导入批次
2. 查看 staging 行
3. 修正校验错误
4. 查看重复候选
5. 选择合并策略
6. 确认入库或拒绝批次

### 事件库管理

支持：

- 搜索事件
- 按年份、地区、状态、置信度筛选
- 查看事件详情
- 编辑事件字段
- 标记争议
- 归档
- 查看审计日志

### 来源管理

在事件详情页可维护来源：

- 新增来源
- 修改 citation、excerpt、URL、作者、出版方
- 调整可靠度
- 标记主来源
- 删除来源

### 关系管理

可维护事件之间的关系，例如：

- 同期
- 因果
- 影响
- 不确定关系

关系用于 Agent 的关联分析。

### 数据质量

数据质量页用于处理：

- 无来源事件
- 低置信事件
- 疑似重复
- 时间异常
- 关系缺证据

每个问题可以标记为：

- open
- resolved
- ignored
- snoozed

### 知识库管理

知识库用于 RAG 检索，支持：

- 导入文档
- 查看 chunk
- 更新元数据
- 停用或归档文档
- 查看版本
- 重切分
- 重算 embedding

知识库 chunk 会被视为不可信上下文，只能作为资料线索，不能作为指令。

### 向量管理

向量页用于查看 embedding 状态和重建任务：

- 查看事件和知识库向量覆盖率
- 创建向量重建任务
- 自动处理 pending jobs
- 手动处理任务
- 查看任务状态

## 8. 安全和审计

系统当前已有几类安全保护：

- Prompt Injection 拦截
- 高风险工具人工确认
- 模型自确认拦截
- RAG、记忆、工具 observation 不可信上下文标记
- RBAC 管理员权限校验
- 安全事件审计

安全事件会写入 `security_audit_logs`，包括：

- event_type
- category
- reason
- run_id
- metadata
- created_at

业务写操作会写入 `event_change_logs`。

## 9. 常见问题

### 登录后请求 `/chat/conversations` 返回 401

说明当前没有有效 session。请重新登录，或确认浏览器没有拦截 cookie。

### 聊天回答一直显示 loading

前端需要正确处理后端 SSE 的 `run_completed` 事件。当前版本已修复：收到 `run_completed` 后会把消息状态保持为完成。

### 后端不应该使用 8000 端口

本项目当前约定后端使用 `19000`。如果看到旧文档或命令写着 `8000`，应改为：

```text
http://127.0.0.1:19000
```

### 普通用户为什么不能确认工具操作

确认操作可能修改数据库，因此需要管理员角色。普通用户可以查看结果和等待确认提示，但不能执行确认恢复。

### 为什么知识库资料不能直接当指令

知识库、网页、记忆、工具返回都可能包含恶意文本。系统会把这些内容标记为不可信上下文，只允许作为事实线索，不允许覆盖系统规则或跳过人工确认。

## 10. 推荐使用方式

普通用户：

1. 登录。
2. 新建会话。
3. 提出具体历史问题。
4. 查看回答、事件卡片和引用。
5. 按主题整理聊天组。

管理员：

1. 登录管理员账号。
2. 维护事件库和来源。
3. 导入新历史数据。
4. 处理数据质量问题。
5. 管理知识库和向量任务。
6. 对 Agent 生成的高风险修订草案进行人工确认。
